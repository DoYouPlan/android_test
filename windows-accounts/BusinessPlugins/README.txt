ДВА ПЛАГИНА ДЛЯ «ХРЮШКИНЫХ ПОДУШЕК» · версия 1.0
Совместимость: Бухгалтерия Windows 3.0, API плагинов 1.
Приложение обновлять и Python устанавливать не требуется.

УСТАНОВКА
1. Распакуйте общий архив. Внутри два отдельных пакета ZIP:
   Profitability_1.0.zip и StockPlanner_1.0.zip.
2. В программе откройте «Плагины → Установить ZIP».
3. Выберите первый пакет. Затем так же установите второй.
   Сами пакеты перед установкой распаковывать НЕ нужно.
4. По очереди выделите плагин, нажмите «Включить / выключить» и «Запустить».
В окне отчёта можно выгрузить таблицу в CSV.
Плагины работают по снимку всей базы. Фильтр периода и поиск основного
окна программы на них не влияют. Они не изменяют базу, не обращаются в сеть
и не размещают заказы. Для нового расчёта после изменений нажмите «Запустить».
Дата расчёта берётся с часов компьютера. Проверьте их правильность.

1. «НА ЧЁМ ЗАРАБАТЫВАЕМ»
Группирует продажи по изделию, категории/каналу и складу.
Для каждого показывает количество, выручку, удержанные комиссии,
известную себестоимость и маржу. Два среза: все даты до сегодня и
последние 30 календарных дней включительно.
Маржа = выручка минус комиссии минус себестоимость проданных изделий.
Это не чистая прибыль бизнеса: общие расходы на продвижение, связь и
другие услуги между изделиями не распределяются.
Если в группе хотя бы у одной продажи нет поля _cost, маржа не считается:
в таблице «Не рассчитана» и число продаж без себестоимости. Нулевая явно
записанная себестоимость считается известной. Проставляйте её осмысленно.
Текущую стоимость из карточки товара плагин в прошлые продажи не подставляет.
Уточните себестоимость в самих операциях и повторите запуск отчёта.
Продажи без даты попадают только в срез «Все даты» и отмечаются.
Отменённые и будущие продажи исключены. Выплаты партнёра не создают выручку.
Строки отсортированы по выручке, а не по марже с неполными затратами.
Ограничение системы — 10000 строк и 1 МБ отчёта. Все даты остаются отдельным срезом.

2. «ЧТО СШИТЬ И ПЕРЕДАТЬ ПАРТНЁРУ»
Рассчитывает текущий склад по проведённым операциям на сегодняшний день.
Спрос — продажи за последние 60 дней, целевой запас — на 21 день.
Минимальный запас: 2 изделия дома и 1 у партнёра.
Цель по каждому складу = максимум из минимального запаса и округлённого
вверх прогноза по средней скорости продаж. Товар включается в предложение
склада, если у него есть положительная цена для этого склада, остаток
или продажи за период. Нулевые карточки без истории не требуют пошива.
При пустой истории рекомендует только минимум, а не прогноз спроса.

Сначала предлагает передать партнёру свободный домашний запас сверх
домашней цели. Затем считает пошив недостающего количества для обоих складов.
«Передать» — только из уже имеющегося свободного домашнего запаса.
«Сшить» — общий недостающий объём: дома и для партнёра вместе.
Пример: дома 10, у партнёра 0, цели 2 и 1 → передать 1, сшить 0.
Пример: дома 0, у партнёра 0, цели 2 и 1 → передать 0, сшить 3.
Из сшитого во втором примере потом потребуется оставить 2 дома и передать
1 партнёру; этот шаг нужно провести самостоятельно, плагин его не записывает.
При отрицательных остатках вместо плана выводится «Сначала сверить».
Сезонность, ткани, доступное время, партии, заказы в работе и ожидаемые
поступления не учитываются. Это ориентир для решения, не обязательный заказ.
Продажи без даты не формируют скорость спроса, но их складское движение
учитывается по правилам программы. Дата искажения старых остатков видна
в исходном журнале. Учитываются только склады Дома и Зверёк Аморе.

НАСТРОЙКИ
Установленные файлы находятся в:
%LOCALAPPDATA%\HryushkiAccounts3\plugins\hryushki.profitability
%LOCALAPPDATA%\HryushkiAccounts3\plugins\hryushki.stockplanner

profit.settings.json: recentDays — число дней недавнего периода, по умолчанию 30.
stock.settings.json:
lookbackDays — сколько дней продаж анализировать (60);
targetDays — на сколько дней нужен запас (21);
minimumHome — минимальное количество дома (2);
minimumPartner — минимальное количество у партнёра (1).
Для дней допускается целое число 1–3650, для минимумов — число 0–10000.
Минимум применяется только к товару, который предлагается на данном складе.
Изменяйте JSON в Блокноте при закрытом окне отчёта; затем запускайте плагин снова.
Не меняйте plugin.json и DLL. Если JSON испорчен, плагин покажет ошибку,
а база останется без изменений. Исходные настройки можно взять из пакета ZIP.
При удалении плагина программа удаляет и его настройки.

НА БУДУЩЕЕ
Следующие полезные дополнения: сверка расчётов с партнёром; проверка качества
учёта (дубли, пропущенные цены и даты); калькулятор раскроя и себестоимости;
календарь заказов и сроков. Для дополнений, записывающих операции, потребуется
расширить API: текущая версия рассчитана на отчёты.

# Хрюшкины подушки — Бухгалтерия Android 2.0

Android 8.0 и новее. Без Python, сервера и интернет-соединения.

## Переход с первой версии

Версия 2.0 устанавливается отдельно под именем «Хрюшкины подушки 2». Старое приложение можно оставить до завершения переноса. Такое размещение сохраняет доступ к старому клиенту и его файлам: у пробной версии 1.0 был временный ключ сборки.

1. В старом приложении выгрузите актуальную базу JSON, если добавляли записи только там. Либо сохраните полную резервную копию из ПК 3.0 («База и копии → Сохранить копию»).
2. Установите подписанный APK версии 2.0 и запустите новое приложение с фирменной иконкой.
3. «База и копии → Импортировать JSON с компьютера», выберите файл и подтвердите замену пустой базы.
4. Сверьте количество операций, товары и остатки. Закройте приложение и откройте снова: база сохранится.

После первого импорта база хранится внутри приложения и автоматически сохраняется при каждом изменении. Внешний JSON не обновляется автоматически. Для обмена с ПК экспортируйте полную базу либо используйте «Записать изменения в исходный JSON». Последняя команда проверяет, не изменился ли внешний файл. Если он был изменён на ПК, сохранение в него блокируется: сначала выгрузите телефонную копию под другим именем и сверьте данные.

Не ведите разные несведённые копии одновременно: автоматического объединения и облачной синхронизации нет. Импорт заменяет текущую рабочую базу, а не добавляет операции. Перед заменой сохраняется внутренняя копия.

Для Android 2.0 нужен полный JSON из ПК 3.0. Старую команду ПК «Копия для Android 1.0» использовать не нужно: она исключает отменённые записи и историю правок.

## Возможности

- Все 13 типов операций ПК 3.0, включая производство, движения между складами, материалы, вложения и вывод средств.
- Выручка, расходы, результат с учётом известной себестоимости, движение денег, долги покупателей и партнёра; выплаты не создают повторную выручку.
- Комиссии, частичная оплата, себестоимость конкретной продажи.
- Редактирование: нажать карточку операции → «Изменить»; исходная запись сохраняется в истории. Отмена требует причины и оставляет запись в журнале.
- Проверка остатков по датам и защита от оплаты сверх долга. Исторические отрицательные остатки показываются для сверки; новые операции не могут их ухудшить.
- Товары и цены: отдельные цены дома и партнёру, себестоимость, артикул, модель, ткань и размер.
- Материалы: единицы, начальный и текущий остаток, закупки и расход с дробным количеством.
- Поиск, фильтр периода, CSV журнала, склада, каталога и материалов.
- Полный JSON с сохранением дополнительных полей, отмен и истории ПК; 30 внутренних автоматических копий, восстановление и экспорт резервной копии.
- Фирменная адаптивная иконка; зелёное оформление; сохранение черновика формы при повороте экрана.
- Плагины в мобильной версии не подключаются.

## Артикулы

Одна повторяемая комбинация модели, ткани и размера — одна карточка с уникальным названием и артикулом. Например:

- «Лежанка · зелёный флис» — `LZ-001`.
- «Лежанка · принт Листья» — `LZ-002`.

Цена и склад в артикул не включаются. Изменение цены не требует нового артикула. Пустой артикул разрешён для старого каталога; одинаковые заполненные артикулы запрещены без учёта регистра. Название служит связью с операциями для совместимости с ПК 3.0: если у карточки уже есть операции, переименование защищено. Артикул можно добавить или исправить без пересчёта остатков.

ПК 3.0 сохраняет дополнительные поля карточек, но не показывает артикулы в интерфейсе. Для их отображения на ПК понадобится отдельное обновление Windows-клиента. Записи, в которых ткань неизвестна, оставляйте в прежнем неуточнённом варианте. Не распределяйте старые остатки между новыми карточками без фактического пересчёта.

Стоимость в карточке — подсказка для новой продажи. Историческая себестоимость хранится в операции и не меняется при редактировании каталога. Если себестоимость не заполнена, результат отмечается предварительным. Нулевая стоимость карточки не подставляется как подтверждённая себестоимость.

## Резервирование

Внутренние копии находятся в данных приложения и удаляются при удалении самого приложения. Регулярно экспортируйте JSON в отдельную папку / на компьютер. При повреждении внутренней базы приложение не подменяет её пустой базой: открывает экран восстановления с выгрузкой исходного файла.

Приложение предназначено для управленческого учёта. Оно повторяет функции ПК 3.0 и не добавляет предоплаты, автоматические нормы расхода ткани или налоговую отчётность.

## Сборка и проверка

Gradle 8.9, Java 17, Android SDK 35, Android Gradle Plugin 8.7.3.

```
gradle -p hryushki :app:assembleDebug :app:assembleDebugAndroidTest
```

GitHub Actions запускает проверку на Android 15: расчёты, частичная оплата, отмены, историческая себестоимость, дробные материалы, артикулы, редактирование с историей, копирование и восстановление базы, открытие экранов. Отдельная проверка сохраняет маркер, принудительно останавливает процесс и проверяет сохранение после повторного запуска.

APK из CI имеет временную отладочную подпись. Пользовательский APK подписывается отдельно постоянным ключом. Ключ и пароль не размещаются в репозитории.

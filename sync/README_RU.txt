ХРЮШКИНЫ ПОДУШКИ — ТЕСТ СИНХРОНИЗАЦИИ 0.1

Это отдельные тестовые приложения для Windows и Android. Рабочие программы, их базы и приложение клиентов / заказов не меняются. Используйте только вымышленные операции. Для первого подключения требуется пустая база.

ПРОЕКТ
https://jkybdiulsztoilkwmhij.supabase.co
Адрес и публичный ключ уже включены в тестовые приложения. Секретный ключ и пароль базы не нужны. Данные доступны только вошедшему аккаунту, который владелец проекта отдельно допустил к тесту.

1. СОЗДАТЬ ТЕСТОВЫЙ АККАУНТ
В панели Supabase откройте ваш проект → Authentication → Users → Add user → Create new user.
Задайте email и пароль тестового аккаунта. Если есть Auto Confirm User — включите его, чтобы вход не требовал письма подтверждения.
Это пароль пользователя приложения, не пароль PostgreSQL. Его не нужно никому присылать.
На ПК и телефоне войдите ОДНИМ этим аккаунтом. Другой аккаунт получит отдельную изолированную базу.

2. УСТАНОВИТЬ ТАБЛИЦЫ И ЗАЩИТУ
Откройте SQL Editor → New query. Скопируйте весь текст Server/01_schema.sql и нажмите Run.
Скрипт создаст отдельные таблицы hry_sync_* и функцию обмена; существующие таблицы не удаляет.

3. ДОПУСТИТЬ АККАУНТ
Откройте Server/02_allow_user.sql любым текстовым редактором. В строке chosen замените ВСТАВЬТЕ_EMAIL_ТЕСТОВОГО_АККАУНТА на email из шага 1, оставив одинарные кавычки.
Скопируйте исправленный скрипт в новую SQL-запрос и нажмите Run.
Не заменяйте поля приложения секретным ключом service_role / Secret key.

4. ЗАПУСТИТЬ КЛИЕНТЫ
Windows: распакуйте папку Windows и запустите Hryushki_Accounts_Sync_Test.exe. Python не нужен. Программа использует свою папку HryushkiAccountsSyncTest в профиле Windows.
Android: установите Hryushki_Accounts_Sync_Test.apk. Оно устанавливается отдельно от рабочей бухгалтерии, под названием «Хрюшки · Sync Test». Требуется Android 8.0 и новее.

В обоих приложениях:
Синхронизация → Войти → email и пароль тестового аккаунта → Подключить пустую базу → Обмен сейчас.
Первое устройство может заполнить облако тестовыми данными, второе получит их в свою пустую базу.
Если уже добавили записи до первого подключения, используйте новую пустую тестовую базу. Рабочие базы пока не импортируйте.

5. ПРОВЕРИТЬ ОБМЕН
• На ПК создайте тестовый товар «Тестовая лежанка» с ценой 680.
• Дождитесь обмена / нажмите «Обмен сейчас». На телефоне товар должен появиться в каталоге после обмена.
• На телефоне измените цену на 700. После обмена она должна обновиться на ПК.
• На телефоне выключите интернет, добавьте расход «Тестовая упаковка» на 10 рублей. Запись должна остаться локально. Верните интернет и выполните обмен — она должна прийти на ПК ровно один раз.
• Отключите интернет на обоих устройствах, измените цену одного товара по-разному. Включите связь и выполните обмен на каждом. Для второго изменения должен появиться конфликт с выбором варианта.
• Для проверки продаж сначала внесите тестовое производство / начальный остаток. Продажу сверх наличия программа и сервер не примут.

КАК РАБОТАЕТ
Изменения записываются локально до отправки. Обмен — после изменения и примерно раз в минуту, пока приложение открыто. В Android фоновая синхронизация при полностью закрытом приложении в этой версии не гарантируется.
Каждая запись получает постоянный идентификатор. Числовой номер операции на разных устройствах может отличаться — это локальный номер для отображения, а не идентификатор обмена.
Операции, товары и материалы синхронизируются отдельно. Жёсткое удаление не предусмотрено: используйте отмену операции. Карточки с одинаковым названием распознаются как один объект; разные правки требуют выбора.
При конфликте не выбирается победитель по часам телефона: нужно явно нажать «Взять из облака» либо «Оставить местное». Последний вариант отправится с учётом новой версии записи.
Если две независимые продажи создают нехватку либо выплата превышает долг, весь пакет изменений на сервере откатывается. Локальные записи остаются на месте: их нужно проверить, исправить или отменить и повторить обмен.
Изменения, внесённые пока выполнялся сетевой запрос, не должны теряться: они остаются в очереди на следующий обмен.

ХРАНЕНИЕ
Пароль не сохраняется. Токены входа защищены DPAPI текущего пользователя Windows / ключом Android Keystore. JSON базы не содержит токенов.
Локальные резервные копии остаются включены. Выгрузка JSON — копия, а не способ параллельной синхронизации через облачную папку.
На сервере сохраняются прежние версии исправленных записей. Локальная история правок сохраняется на устройстве; полный просмотр серверной истории и восстановление из неё в этом прототипе ещё не добавлены.

ОГРАНИЧЕНИЯ ТЕСТА
До 400 изменений за один обмен; оставшаяся очередь отправляется следующим обменом. Ориентир — до 5000 записей на аккаунт. Тестовая версия не переносит рабочую бухгалтерию автоматически и не синхронизирует настройки приложения, список нестандартных складов, плагины и приложение клиентов.
Сервер проверяет итоговые остатки / долги; хронологические проверки локальных операций остаются в клиентах. Это прототип для совместной проверки, а не завершённый перенос рабочего учёта.
Доступность из домашнего интернета и МТС нужно проверить на ваших устройствах.

ЕСЛИ НЕ ПОДКЛЮЧАЕТСЯ
• «Invalid login credentials» — проверьте email и пароль пользователя приложения.
• «Email not confirmed» — подтвердите email пользователя в Supabase.
• «Аккаунт не допущен» — выполните 02_allow_user.sql с правильным email.
• HTTP 404 / функция не найдена — выполните 01_schema.sql, подождите обновления API и повторите.
• Нет связи — изменения остаются локально. Проверьте сеть и повторите обмен.
• На Free проект Supabase может приостанавливаться из-за неактивности — проверьте статус проекта в панели.

ПРОВЕРКИ
Скрипты проверяются на отдельной PostgreSQL 16; клиенты — на Windows и эмуляторе Android 15. Проверки включают конфликты, повторные запросы, сохранение локальных изменений во время обмена, разные локальные номера операций, изоляцию пользователей и запрет продажи сверх остатка.
Полный обмен через ВАШ проект ещё не проверен: для него сначала нужно выполнить шаги 1–3 и войти в приложения.
